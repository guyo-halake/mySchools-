# Project Rules - School System

You must adhere to these rules at all times. Failure to follow these rules is unacceptable.

## 1. Scope Control
- **Only code what is explicitly requested.**
- Do not touch, modify, or "refactor" any code that is not directly related to the current task.
- Stay within the bounds of the instructions provided by the USER.

## 2. Design Integrity
- **Understand and follow the application's existing theme and design.**
- Do not create your own designs or introduce new UI patterns unless explicitly asked.
- Maintain consistency with the current aesthetic (Minimalist, Professional, Premium).

## 3. Data Authenticity
- **No mock data.**
- Every feature or code block must be connected to the live database (Supabase/Prisma/SQL).
- Ensure data fetching and persistence are fully functional.

## 4. Error-Free Code
- **Do not deliver code with errors.**
- You are not finished until all errors (syntax, runtime, linting) are resolved.
- Always check for errors as you code and fix them immediately.

## 5. Natural Language
- **No "AI words" or overly institutional jargon.**
- Use normal, natural English in the UI and documentation.
- Avoid robotic or repetitive AI phrasing.

## 6. No AI Designing
- Do not use generic "AI-generated" layouts or styles.
- Stick to the specific, high-fidelity design style requested by the USER in previous sessions (Mobile-first, Tabbed architecture, Minimalist).
